# Demo roster (synthetic)

Generated by `scripts/seed_demo_data.py` (deterministic seeds). Every client, supplier, customer, invoice and amount is invented. Not tax data, not for filing, not a real portal format.

One folder per fictional registration and period, each with `sales_register.csv`, `purchase_register.csv` and `gstr2b_demo.csv`. Files contain deliberate issues so the demo shows real behaviour:

- Purchases: one taxable-value mismatch, one date conflict, one invoice missing from the statement (supplier not yet filed), one statement-only invoice, one duplicate book entry, one invalid date.
- Sales: one total that does not add up, one unsupported credit note, one duplicate invoice.

The script drives each client to a different workflow state through the real API (so everything is validated and audited):

| Client | Period(s) | Final state |
|---|---|---|
| Kaveri Retail | 2026-07, 2026-08 | Approved, filing reference recorded (user-reported) |
| IndusCart E-commerce | 2026-07 / 2026-08 | Filed / draft ready for approval |
| Nilgiri IT Services | 2026-08 | Approved, then a sales review changed → approval out of date |
| Deccan Fabricators | 2026-08 | Reconciled, ITC decisions pending |
| Malabar Kitchen | 2026-08 | Files uploaded, not committed |
| Sahyadri Wholesale | 2026-08 | Sales half reviewed; purchases not committed |
| Konark Consulting | 2026-08 | Approved, then reopened with a reason |
| Brahmaputra Logistics | 2026-08 | Awaiting files |

Run against the API connected to the database you want to fill: `python scripts/seed_demo_data.py --api http://127.0.0.1:8000`. Re-running skips clients that already exist.
